# 三平台硬约束与校验项

## 一、输入稿件的固定格式

阶段 B 的解析器依赖这个结构，写作技能必须产出它：

```markdown
# <文档标题>

> 元信息第一行
> 元信息第二行

---

## 【备选标题】

1. **<标题 A>**（公式说明）
   → ★推荐，理由：……
2. **<标题 B>**（公式说明）
   → 备选，理由：……

---

## 【正文】

**01**

第一段。

第二段。

**02**

……

---

## 【可截图金句】

· 金句一

· 金句二

---

## 【发布建议】

- **封面**：……
- **话题**：#标签1 #标签2
- **发布时间**：……
```

解析规则：

- 一级标题 `# ` → 文档标题（兜底用）
- `## 【X】` → 章节分隔
- `**01**` → 正文分段标记
- `### 小标题`（可选，写在正文内）→ 该章小标题，会替换掉 `01` 作为章节标题
- 选标题：优先取带 `★` 的候选；没有则取第一条；都没有则回退文档标题
- 话题标签：从【发布建议】里抓 `#标签`（2–12 字）

## 二、飞书云文档（阶段 C）

- 文档结构：`<title>` → `<h1>章节>` → 块
- `<callout emoji="📌" background-color="light-blue">` 里只能放 `p` / `ol` / `ul` / `checkbox`
- 标题层级不跳级；`<li>` 内不套 `<p>`
- 存根内容默认只存**正文 + 可截图金句**，`--with-notes` 才带过程稿
- 表格回填：`{"update_records":{"<rid>":{"存档文档":"<url>","状态":["已写待发"]}}}`

## 三、言序 / 公众号草稿箱（阶段 D-1）

| 约束 | 值 | 备注 |
|---|---|---|
| `title` 长度 | ≤ 30 字 | 超限会被服务端直接拒绝 |
| `abstract` 长度 | ≤ 100 字 | 建议有信息量，别写"本文介绍了……" |
| `chapters` | 不能为空 | 空数组直接拒绝 |
| `cover_img` | ≤ 2MB | 公网可访问的 http(s) URL |
| `image` 块单张 | ≤ 1MB | 推荐 200–800KB、长边 ≤1200px |
| 结构 | 扁平 | `intro` / `chapters` 与 `title` 同级，**不要套 `content` 包裹** |
| blocks 类型 | 仅 4 种 | `paragraph` / `image` / `list` / `table` |
| `content` | **必须纯文本** | 塞 HTML 标签 = 废稿（言序无 update 接口，只能重建） |
| 重复标题 | 禁止 | `intro` 和章 `title` 不要写成 block，否则两层标题 |

`render_platforms.py` 会在提交前拦下 `content` 里的 `<` `>` 和残留 `**`。

**言序没有 update 接口** —— 建稿之后发现错只能重建，旧稿会留在后台。
所以阶段 B 的校验必须在前，不允许"先建再改"。

## 四、头条号（阶段 D-2）

| 约束 | 值 |
|---|---|
| 标题上限 | 30 字（超出只能截断或改写） |
| 正文格式 | 纯文本，逐行一段（`\n` 分隔，无空行分段） |
| 引号 | 中文弯引号 `“”`，不用 ASCII 直引号 |
| 封面内联 | 需压到 ~100KB 再 base64（页面内自建 File 注入） |
| 声明 | 勾选「个人观点，仅供参考」 |
| 发布 | 二次确认弹窗，必须点掉 |

正文粘贴**不能**用 `bsk fill`（ProseMirror 聚焦时会重渲染，元素失效），
必须 `evaluate` 注入 ClipboardEvent。见 `env-constraints.md`。

## 五、公众号头图（阶段 A 产出）

| 项 | 值 |
|---|---|
| 比例 | 2.35:1 |
| 朋友圈安全区 | 横向 28.7% ~ 71.3%（只保留正中央 1:1 方形） |
| 主文案横向宽度 | **严格 ≤ 画面总宽度的 30%** |
| 排版方向 | **必须水平居中**，严禁竖排、严禁靠左靠右 |
| 禁止 | 二维码、任何品牌 logo 与水印、乱码错别字、多余小字 |

生成后必须目视复核两点：主文案是否居中、横向宽度是否超 30%。

## 六、跨平台字数口径

| 口径 | 含义 | 参考值 |
|---|---|---|
| `cjk_chars` | 纯中文字数 | 写作技能的字数下限按这个口径（1300+） |
| `total_chars` | 含标点的可见字符数 | 头条后台显示的"字数"接近这个 |
| `paragraph_count` | 段数（含 `01`–`05` 标记行） | 头条编辑器里 `<p>` 的数量 |

`render_report.json` 里三个口径都有，汇报时说明用的是哪个，避免"字数对不上"的误会。
